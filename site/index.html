deslopify

Unlock effortless, human-sounding writing with a powerful, seamless AI solution. An agent skill for editing AI writing habits out of emails, papers, web pages, and slop grenades. It keeps the facts, caveats, and voice the reader needs.

The skill is a set of reviewed dos and don’ts. Each rule has an example that follows it and a counterexample that breaks it. Some apply to every model; others were seen in one company’s models, or in one model in one setting.

Install

Copy the whole deslopify/ folder into your project’s skills directory, subfolders included; SKILL.md links into them. There is nothing else to install.

Use it

Give it the draft and say who will read it. Call it with /deslopify in Claude Code or $deslopify in Codex.

$deslopify Edit this draft for its audience while preserving meaning, useful facts, and needed qualifications.

How it picks rules

Writing
Wording, structure, and meaning.
Taste
A stated aesthetic preference. Not a test of correctness.
Design
Layout, visuals, and interactions.

It reads the rules for every model, then adds a company’s or model’s rules only when you name one. It does not guess the model from a draft’s style, and it does not stretch one model’s habit to all of them.

Some text is never cut for being “AI-sounding”: UI labels, accessible names, instructions, errors, product facts, and required disclosures.

To see only the rules that apply to a task, run the bundled script (Python 3, standard library only):

python3 .claude/skills/deslopify/scripts/rules.py select --category writing --company openai --model gpt-5.5

Add --format json for structured records. Leave out --company and --model for the every-model rules only. For Codex, use the .agents/skills path.

Add or change a rule

Fill out the rule form on GitHub. You don’t need to clone anything or write code. Give one example that follows the rule and one counterexample that breaks it, choose the narrowest scope your observation supports, and say why it helps.

Open the rule form

A maintainer runs a GitHub Actions workflow that turns the issue into a pull request. Merging it updates the skill and this page.

Editing the files directly

Each rule is one JSON record in deslopify/rules/<category>/<id>.json. Keep the ID when you revise a rule. Then run the checks in CONTRIBUTING.md.

{
  "id": "avoid-empty-superlatives",
  "title": "Replace empty praise with a concrete benefit",
  "category": "writing",
  "direction": "do",
  "scope": "all",
  "company": null,
  "model": null,
  "model_state": null,
  "context": "Product descriptions. Preserve useful specifications and required disclosures.",
  "rule": "Replace unsupported praise with a specific benefit the product actually offers.",
  "example": "Export all invoices as a CSV file.",
  "counterexample": "Unlock an incredible, seamless invoice experience.",
  "rationale": "Readers can decide whether the product solves their problem.",
  "evidence": "Illustrative example, not a recorded model output."
}
